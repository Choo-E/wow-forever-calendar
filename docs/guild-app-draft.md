# 길드 관리 종합 앱 초안

길드: **오늘도 평화로운 호드 생활** (WoW: Forever, 호드)
작성일: 2026-11-11 · 상태: **초안 → 확정안 정리 중 (10장이 최신, 앞 장과 다르면 10장을 따른다)**

## 1. 목표

지금의 "일정 캘린더"를 **길드 운영 도구**로 키운다. 길드장과 간부가 한 곳에서 일정, 레이드, 이벤트, 멤버를 관리하고, 길드원은 참석 신청과 일정 확인을 한다.

## 2. 가장 먼저 정해야 할 것: 공개 범위

지금 사이트는 **누구나 볼 수 있는 정적 사이트**(GitHub Pages)라서 일부만 숨기는 기능이 없다. 멤버 관리·출석·메모 같은 정보는 **로그인한 길드원만** 봐야 하므로, 사이트를 두 영역으로 나눈다.

| 영역 | 누가 보나 | 들어가는 것 |
|---|---|---|
| **공개 영역** (지금 사이트) | 누구나 | 공식 일정, 패치·소식, 공개 길드 일정, 길드 소개·모집 안내 |
| **길드원 전용 영역** (새로 만듦) | 로그인한 길드원 | 레이드 편성·참석 신청, 멤버 명단, 출석, 길드 내부 공지 |
| **간부 전용 기능** | 길마·간부 | 멤버 관리, 신청 승인, 메모, 권한 설정 |

> 공개 저장소(GitHub)에는 **개인정보를 절대 올리지 않는다.** 멤버 정보는 별도 데이터베이스에 둔다.

## 3. 탭 구성안

```
[홈] [일정] [레이드] [이벤트] [멤버] [소식] [관리]
 공개  공개   전용     전용/공개  전용   공개   간부
```

### 홈 (대시보드)
- 가장 가까운 일정 D-day, 오늘 일정, 다음 레이드 시간
- 길드 공지(고정), 내 참석 신청이 필요한 일정 알림

### 일정 (지금의 캘린더를 확장)
- 공식 일정 + 패치 + 길드 일정(레이드·이벤트)을 한 달력에 통합 (이미 있음)
- 필터: 전체 / 공식 / 길드 / 내 참석 일정

### 레이드
- **정기 레이드 일정**: 요일·시간 반복 (예: 매주 화·목 21:00)
- **참석 신청(RSVP)**: 참석 / 불참 / 미정 + 사용할 캐릭터·역할(탱/힐/딜)
- **편성**: 10인·20인·40인 공대, 역할별 인원 균형 표시, 대기 명단
- **기록**: 진행 결과(클리어한 보스), 참석자, 획득 아이템 메모
- **공략·규칙 링크**: 루팅 규칙, 필수 소모품, 공략 영상 링크

### 이벤트
- 길드 모임, 대회, 기념일(매년 반복 지원 — 이미 있음)
- 참가 신청과 인원 제한, 후기·사진 링크

### 멤버
- **명단**: 캐릭터명, 직업, 역할, 등급(길마/간부/정회원/신입), 가입일, 최근 접속
- **부캐 묶음**: 한 사람의 여러 캐릭터를 하나로 묶기
- **출석률**: 레이드·이벤트 참석 비율 (간부 전용)
- **가입 신청 처리**, 휴면·탈퇴 관리, 간부 메모(간부 전용)

### 소식
- 포에버·전체 와우 소식 자동 한글 타임라인 (이미 있음)

### 관리 (간부 전용)
- 권한 설정, 디스코드 알림 설정, 데이터 내보내기(백업)

## 4. 데이터 구조 (초안)

| 이름 | 주요 내용 |
|---|---|
| `members` | 사람 단위: 표시 이름, 등급, 가입일, 상태, 디스코드 계정 연결 |
| `characters` | 캐릭터 단위: 이름, 직업, 역할, 레벨, 소유 멤버 |
| `events` | 길드 이벤트·일정 (지금의 `guild.json` 내용) |
| `raids` | 레이드 일정: 던전, 날짜·시간, 인원 규모, 상태 |
| `signups` | 참석 신청: 누가, 어떤 일정에, 어떤 캐릭터·역할로, 응답 |
| `attendance` | 실제 참석 기록 (출석률 계산용) |
| `raid_results` | 진행 결과, 보스 킬, 메모 |
| `announcements` | 공지, 고정 여부, 공개 범위 |

## 5. 구현 방식 선택지

정적 사이트만으로는 로그인·데이터 저장이 안 되므로 "저장 장소와 로그인"이 필요하다.

| 방식 | 설명 | 장점 | 단점 |
|---|---|---|---|
| **A. Supabase (추천)** | 무료로 시작 가능한 온라인 데이터베이스 + 로그인 + 권한 기능 제공. 지금 사이트는 그대로 두고 연결 | 서버를 직접 안 만들어도 됨, 디스코드 로그인 지원, 권한(간부/일반) 규칙을 DB에 설정 | 계정 가입 필요, 무료 한도 있음 |
| B. Firebase | 구글의 비슷한 서비스 | 자료 많음 | 구조가 달라 지금 코드와 맞추기 번거로움 |
| C. 직접 서버 제작 | Node 서버 + DB를 직접 구성 | 자유도 높음 | 서버 비용, 보안·백업을 직접 관리, 초보에게 부담 |
| D. 디스코드 봇 중심 | 디스코드 안에서 명령어로 관리 | 길드원이 이미 쓰는 곳 | 화면이 제한적, 봇 호스팅 필요 |

**로그인**: 길드원이 이미 쓰는 **디스코드 계정으로 로그인**하는 방식을 추천한다. 간부 권한은 디스코드 역할(Role)과 연결할 수 있다.

## 6. 길드 명단 가져오기 (와우 API 조사 결과)

**결론: 포에버에서 Blizzard 공식 API로 길드 명단을 받아올 수 있다고 확인된 자료는 없다.**

- 기존 길드 명단 API는 **서버(렐름) 이름**과 길드 이름으로 주소를 만든다. 포에버는 **서버 구분이 없는 게임**이라 이 방식이 그대로 맞지 않는다.
- 클래식 계열은 공식 API 지원이 제한적이고 일부는 작동하지 않는다는 개발자 포럼 글이 있다.
- 포에버용 API가 공개 문서로 나와 있는지 확인되지 않았다. (Blizzard 개발자 포털에서 직접 확인 필요)

| 방법 | 가능성 | 설명 |
|---|---|---|
| 직접 입력·붙여넣기 | ✅ 확실 | 게임 내 명단을 보고 입력하거나 표로 붙여넣기. 처음 한 번만 하면 됨 |
| 게임 안 애드온으로 내보내기 | 🔶 확인 필요 | 애드온이 명단을 파일로 내보내면 사이트에 올려 갱신. 포에버에서 쓸 수 있는 애드온이 있는지 확인해야 함 |
| Blizzard 공식 API | ❓ 불확실 | 개발자 포털(developer.battle.net)에 앱을 등록하고 API 키를 받아 시험해야 하지만, 포에버가 지원되는지부터 불명확 |
| 길드원 본인 등록 | ✅ 확실 | 길드원이 직접 캐릭터를 등록하고 간부가 승인 |

**권장**: 처음에는 **직접 입력·붙여넣기 + 길드원 본인 등록**으로 시작하고, 포에버 API가 공개되면 자동 가져오기를 추가한다. API 키가 필요해지면 GitHub 비밀 저장소에 넣고 대화창에는 붙여넣지 않는다.

## 7. 개인정보·보안 원칙

- 멤버 정보(디스코드 계정, 출석, 메모)는 **공개 저장소·공개 페이지에 두지 않는다.**
- 필요한 정보만 수집한다. (실명·연락처는 받지 않음)
- 간부 메모와 출석은 **간부만 열람**한다.
- 탈퇴한 멤버의 개인 정보는 삭제한다.
- 비밀 값(API 키 등)은 파일·대화·커밋에 적지 않고 비밀 저장소에만 둔다.
- 정기적으로 데이터를 내려받아 백업한다.

## 8. 단계별 로드맵

| 단계 | 내용 | 계정 가입 |
|---|---|---|
| **0. 설계 확정** | 이 문서의 질문에 답하고 범위 결정 | 없음 |
| **1. 공개 탭 구조** | 현재 사이트를 탭 구조(홈·일정·레이드·이벤트·소식)로 개편. 레이드·이벤트 일정을 공개 화면에 표시. 데이터는 지금처럼 파일로 관리 | 없음 |
| **2. 로그인 + 멤버 명단** | Supabase 연결, 디스코드 로그인, 멤버 명단·권한, 길드원 전용 영역 | Supabase, 디스코드 개발자 앱 |
| **3. 레이드 운영** | 참석 신청, 편성, 출석·결과 기록 | 없음 |
| **4. 자동화** | 디스코드 알림 연동 확대(참석 신청 현황, 레이드 하루 전 알림), 명단 자동 가져오기(가능해지면) | 상황에 따라 |

단계 1은 **지금 구조 그대로**(계정 가입 없이) 만들 수 있어서 바로 시작할 수 있다. 단계 2부터는 길드원 정보를 다루므로 공개 범위 결정이 먼저다.

## 9. 결정이 필요한 질문

1. **길드 규모**: 대략 몇 명인가? (10인/20인/40인 공대를 모두 운영하는가?)
2. **멤버 정보 공개**: 명단을 길드원에게만 보여줄까? 외부 공개(모집용 일부)도 필요한가?
3. **입력 주체**: 간부만 입력하는가, 길드원이 참석 신청·캐릭터 등록을 직접 하는가?
4. **등급 체계**: 길마 / 간부 / 정회원 / 신입 외에 다른 등급이 있는가?
5. **정기 레이드**: 요일·시간·인원 규모는? (12월 10일 공격대 오픈 후 계획)
6. **디스코드**: 길드원 대부분이 디스코드를 쓰는가? (로그인 방식 결정에 필요)
7. **우선순위**: 레이드 참석 신청, 멤버 명단, 출석 관리 중 가장 급한 것은?

## 10. 확정안 (2026-11-11 답변 반영 · 이 장이 최신)

### 10-1. 답변으로 확정된 것

| 항목 | 내용 |
|---|---|
| 규모 | 길드원 약 100명, 저녁 피크 동시 접속 약 40명, **계속 증가**. 40인 공대까지 고려 |
| 멤버 명단 | 지금은 **전체 공개**. 나중에 **"길드원만 보기"로 바꾸는 스위치**를 둔다 |
| 레이드 신청 | 길드원이 **웹에서 직접** 신청 |
| 레이드 만들기 | 간부가 던전·날짜·시간을 직접 입력하거나, **정기 템플릿(예: 매주 토·일 18:00)으로 자동 생성**되어 정해진 때에 신청이 열림 |
| 신청 방식 | 탱/힐/딜 **역할별 정원, 선착순**. 정원 초과는 대기 |
| 최종 확정 | **길마 또는 공대장**이 참석자를 최종 선택 |
| 정기 레이드(시험) | **토요일 18:00, 일요일 18:00** 2타임. 미정이므로 나중에 바꿀 수 있어야 함 |
| 디스코드 | 평소엔 거의 안 쓰지만 **레이드 때는 모두 사용** → 로그인과 알림에 활용 가능 |
| 모바일 | 폰에서 **앱처럼 설치해서** 보고 신청 (설치형 웹앱, PWA) |

### 10-2. 설계 결정

- **명단은 파일이 아니라 데이터베이스에 둔다.** 공개 저장소에 파일로 올리면 나중에 숨길 수 없다. 데이터베이스에 두고 "명단 공개 여부" 설정값으로 공개·길드원 전용을 전환한다.
- **공개되는 명단에는 캐릭터 이름·직업·역할·등급만** 넣는다. 디스코드 계정, 출석, 간부 메모는 어떤 설정에서도 공개하지 않는다.
- **선착순은 서버(데이터베이스) 쪽에서 판정**한다. 동시에 눌러도 정원을 넘지 않게 하기 위해서다. 화면에서만 막으면 안 된다.
- **로그인은 디스코드 계정**으로 한다. 한 사람이 같은 일정에 중복 신청하지 못하게 하고, 신청자를 확인하기 위해서다.
- **설치형 웹앱(PWA)**: 앱스토어 앱이 아니라, 폰 브라우저에서 "홈 화면에 추가"하면 앱처럼 아이콘으로 실행되는 방식. 안드로이드는 크롬의 "앱 설치", 아이폰은 사파리의 "공유 → 홈 화면에 추가". 알림은 아이폰에서 제약이 있을 수 있으므로 **디스코드 알림을 기본**으로 한다.

### 10-3. 레이드 신청 흐름

1. 길드원이 디스코드로 로그인 → 내 **캐릭터 등록**(이름·직업·역할)
2. 레이드 목록에서 **[신청]** → 캐릭터와 역할 선택
3. 그 역할의 정원이 남아 있으면 **신청 순서대로 "신청 완료"**, 가득 차면 **"대기"**
4. **공대장이 최종 참석자를 확정**(대기자 승격 가능)
5. 확정되면 **디스코드 채널에 공대 명단 자동 게시**, 하루 전·1시간 전 알림
6. 취소하면 대기자 1순위에게 승격을 알림

### 10-4. 권한

| 등급 | 할 수 있는 일 |
|---|---|
| 길마 | 모든 것, 권한 설정 |
| 공대장 | 레이드 만들기·수정, 참석자 확정 |
| 간부 | 멤버 관리, 일정·이벤트 관리 |
| 길드원 | 캐릭터 등록, 레이드 신청·취소 |
| 손님(비로그인) | 공개 영역(일정, 소식, 공개 명단 설정 시 명단) |

### 10-5. 디스코드 신청 봇 vs 우리 웹앱

| | 디스코드 신청 봇 (예: Raid-Helper 등) | 우리 웹앱 |
|---|---|---|
| 시작 속도 | 몇 분이면 설정 | 개발 필요 (수 주) |
| 길드원 접근 | 디스코드 안에서 바로, **알림도 자동** | 주소(앱 아이콘)로 들어와야 함 |
| 역할 정원·선착순 | 대부분 지원 | 원하는 대로 직접 설계 |
| 우리 캘린더·명단·출석과 연동 | 어려움 (별도 관리) | **한 곳에서 통합** |
| 출석 이력·통계 | 제한적 | 자유롭게 구현 |
| 비용 | 기본 무료, **고급 기능은 유료인 경우가 많음** (확인 필요) | 무료 서비스 한도 안에서 가능, 한도 초과 시 비용 |
| 의존성 | 외부 서비스가 바뀌거나 중단되면 영향 | 우리가 통제 |
| 유지보수 | 거의 없음 | 오류·보안을 우리가 관리 |

**결론: 둘 중 하나가 아니라 역할을 나눈다.** 웹앱을 기준 시스템(신청, 명단, 출석)으로 두고, 디스코드는 **알림과 음성 대화**에 쓴다. 웹앱이 완성되기 전에 급하게 레이드를 돌려야 하면 신청 봇을 임시로 쓸 수 있다.

#### 레이드 확정 사항

| 항목 | 결정 |
|---|---|
| 등급 | 길마 / 공대장 / 간부 / 정회원 / 신입 그대로 진행. **신입도 신청 가능** |
| 레이드별 정원 | **나중에 정함.** 숫자를 코드에 박지 않고, 관리 화면에서 레이드 템플릿마다 탱/힐/딜 인원을 입력하게 만든다 |
| 공대장 | **템플릿마다 고정 담당자**를 두고, 특정 일정만 **변경할 수 있게** 한다 |

| 신청 마감 | **나중에 정함.** 관리 화면의 설정값으로 만든다. 정해지기 전에는 "레이드 시작 시각까지"로 임시 운영 |
| 중복 신청 | **한 사람이 같은 레이드에 캐릭터 1개만.** (토·일은 별개의 레이드이므로 각각 신청 가능 — 달리 원하면 알려 주세요) |
| 취소 규칙 | 위임받아 **제안 기본값**으로 정함 (아래, 언제든 변경 가능) |
| 던전 | 정해지면 알려 주시기로 함 |

**취소 규칙 기본값 (제안)**
1. 레이드 시작 전까지는 **언제든 취소 가능**
2. 시작 **3시간 이내**에 취소하면 **"늦은 취소"로 기록**해서 공대장에게만 표시 (벌칙 없음, 기록만)
3. 취소가 나오면 **대기 1순위에게 승격 알림**
4. 노쇼(신청하고 불참)는 출석 기록에 표시 (4단계 출석 기능에서)

#### 호드평화유지단 지정 방식

호드평화유지단 = **인게임 길드 관리자**.

| 방법 | 상태 |
|---|---|
| **와우 API로 길드 관리자 목록 자동 가져오기** | ❓ **확인되지 않음.** 길드 계급 정보도 길드 명단 API에 들어 있는데, 포에버(서버 구분 없는 게임)에서 그 API가 지원된다는 근거를 아직 찾지 못했다. 지원이 확인되면 추가하는 **선택 기능**으로 둔다 |
| **디스코드 역할 연동 (추천)** | 디스코드 서버에 "호드평화유지단" 역할을 만들고, 로그인한 사람이 그 역할을 가졌는지로 권한을 판단한다. 길드 관리자가 레이드 때 디스코드를 쓰므로 자연스럽다 |
| **길마가 관리 화면에서 직접 지정** | 가장 확실한 기본 방법. 위 방법들이 안 될 때의 대비책 |

→ **처음에는 "길마가 직접 지정" + "디스코드 역할 연동"으로 시작**하고, 포에버 API가 확인되면 자동 가져오기를 추가한다.

#### 회의 운영 확정 사항
- **주기**: 1~2주에 한 번, 상황에 따라 변동 → 고정 반복이 아니라 **회의마다 다음 회의 날짜를 입력**한다 (원하면 반복 규칙은 선택 기능)
- **서기**: Claude가 맡는 것을 목표로 한다 (아래 자동화 구상)
- **길드원 공개 요약**: 필요. 결정 사항 중 공개로 표시한 것만 **[공지]에 올리고 디스코드 공지 채널에도 자동 게시**
- **회의록 이미지**: 한 장으로 정리한 이미지 필요. 호드평화유지단 분위기의 디자인

#### 회의록 자동화 구상 ("서기 Claude")

**먼저 솔직하게:** 이 앱에서 대화하는 Claude가 디스코드 회의 채널에 직접 들어가 있을 수는 없다. 대신 **우리가 만드는 디스코드 봇이 대화를 모으고, 회의가 끝나면 Claude API로 정리**하는 방식이 된다.

```
회의 시작 (/회의시작 호드평화유지 N차 정기 총회)
   ↓  봇이 지정한 회의 채널의 대화를 모음
회의 종료 (/회의종료)
   ↓  Claude API가 정리: 일시·참석자·안건·논의·결정·후속조치
   ↓  이미지 1장 생성 (호드평화유지단 테마)
   ├─ 웹앱 회의록(호드평화유지단 전용)에 비공개 저장
   ├─ 공개로 표시한 결정 사항만 [공지]에 게시
   └─ 디스코드 공지 채널에 요약 이미지 자동 게시
   ↓  원본 대화 기록은 확정 후 삭제
```

**필요한 것**
| 항목 | 설명 | 누가 |
|---|---|---|
| 디스코드 봇 | 개발자 포털에서 봇 생성, 서버에 초대. 봇 토큰은 비밀 저장소에만 보관 | **직접 가입·생성** (제가 단계별 안내) |
| Claude API 키 | 요약에 사용. Claude 구독과 별개이며 **사용한 만큼 내는 소액 요금** | **직접 발급·충전** |
| 봇이 돌아갈 곳 | 회의 때만 내 PC에서 켜는 방식, 또는 상시 호스팅 | 선택 필요 |
| 참석자 동의 | 회의가 기록된다는 사전 고지 | 길드 운영 |

**현실적인 한계**
- **텍스트 채팅 회의**가 가장 현실적이다. 대화가 이미 글이기 때문이다.
- **음성 회의**를 정리하려면 음성→글 변환이 별도로 필요하다. 정확도 문제, 비용, 그리고 **참석자 전원의 녹음 동의**가 필요하다.
- 개인정보: 회의 중 오간 대화는 회의록 확정 후 원본을 삭제하고, 회의록만 남긴다.
- 요약은 AI가 하므로 **틀릴 수 있다.** 확정 전에 서기(사람)나 의장이 검토하는 단계를 둔다.

**지금 바로 가능한 중간 단계 (비용·봇 없이)**
회의가 끝난 뒤 **대화 내용을 이 대화에 붙여넣어 주시면**, 제가 회의록으로 정리하고 이미지까지 만들어 드릴 수 있다. 웹앱에 자동 업로드는 2단계 이후에 가능하고, 그때까지는 이미지를 디스코드에 직접 올리면 된다.

#### 회의록 이미지 구성안
- 제목: **호드평화유지 N차 정기 총회**
- 일시, 장소, 서기, **참석자 / 불참자**
- **주요 안건**, **결정 사항**, **후속 조치(담당·기한)**, **다음 회의 일정**
- 디자인: 호드의 붉은색·검정·금속 질감, 호드평화유지단 전용 **자체 제작 엠블럼**
- 블리자드의 호드 문장 같은 공식 이미지는 상표·저작물이라, 포에버 로고와 같은 주의가 필요하다. **엠블럼은 자체 제작을 권장**한다.

- **로그인**: 디스코드 로그인만 사용한다. 별도 회원가입·비밀번호 없음 (이메일 가입은 끈다).
